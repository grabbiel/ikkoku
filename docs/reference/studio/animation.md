# Original Studio animation playback

Reviewed 2026-09-25 against the working tree. The [Studio audit](../../component-audit/studio.md) is the feature-status and actionable-backlog index; this page records the narrower source contract and its evidence.

The normal Studio animation path resolves the saved `(group, category, no)` through the recovered `Anime_*` tables. Each executable catalog row carries a hash-verified converted controller state, exact source state ID, clips and bindings. An unknown catalog identity never aliases an action-game idle animation.

`OCIChar.LoadAnime`, its speed/pattern setters, `OnSavePreprocessing`, `CharAnimeCtrl`, and the female/male load paths establish these behaviors:

- Load the catalog controller and play its named state at the saved normalized time. The Animator scalar speed is the saved `animeSpeed`; controller state speed is a separate multiplier.
- Normal catalog entries set body height. They do not apply saved `motion` or H-only option parameters. Those fields remain preserved in scenes without incorrectly affecting a normal controller.
- Authored looping clips wrap their sample phase while retaining the normalized loop counter. Forced nonlooping playback restarts at zero in LateUpdate when time reaches one and discards overshoot for that update.
- Native evaluation runs at a deterministic 60 Hz clock. Incremental playback caches only completed step boundaries; fractional tails never accumulate into later frames. State/height changes and seeks reset the cache, and failed plug-in transactions restore it. This keeps live clock cost independent of scene age while retaining bit-identical fresh samples. Sample animation on the customized/ABMX baseline, restore source kinematic activation/root resets, apply saved/edited FK, then run the configured IK solver. Attachments and guides query that same final pose.
- Original-scene export patches animation catalog IDs, speed, pattern, force-loop, options and evaluated normalized time in their bounded original byte spans. Other records, card identities, order and plug-in trailers remain unchanged. Native saves also retain the current evaluated animation state.

`Tools/reverse/studio_animation.py` extracts normal catalog rows and converts serialized Transform clips locally. It handles streamed initialization samples at `-FLT_MAX`, timed cubic keys, dense samples with an authored begin time, constant curves and flat 1D blend states. `Tools/reverse/analysis/studio_animation_contract.py` hashes the recovered C# sources and produces independent binary32 timing traces. Original assets and trace output stay under `.local/reverse/studio-animation`.

Observed base `00` coverage is 287 executable rows out of 288 normal rows, with 411 referenced clips. The remaining row has `m_LoopBlend=true` and `m_Mirror=false`; generic loop-pose correction remains unsupported. Supplying the original body bundle with `--avatar-bundle` resolves every otherwise unbound hash to `cf_body_lowAvatar` paths absent from both `cf_body_00Avatar` and the converted high-detail skeleton. All 287 executable rows are therefore compatible with the selected high-detail hierarchy: 157 contain only bound tracks, 130 additionally contain low-detail-only tracks, and zero rows have unexplained unbound paths. These optional tracks retain their identities and are skipped, just as in the original high-detail character; they are never guessed onto another bone. This is not coverage of every installed animation mod, H controllers, layered/override controllers, automatic transitions, animation events, root-motion extraction, option-item animation or all dynamic/look-at consumers.

Validation covers timing traces, cubic/dense/constant sampling, state weights and actual pose blending, catalog/file identity and hash checks, unchanged-byte reversal of animation edits, and a clothed head-200/bone-1 source-format fixture. Its animation poses differ at 0 and 0.5 seconds; attachment matrices agree with evaluated rig matrices; exporting the evaluated normalized time and reloading restores exactly equal local matrices. Existing FK roundtrip tests continue to compare all 40,490 deformed vertices exactly.

In the retained validation run, the original Unity 5.6.2 player was also executed in a private validation copy with a freshly constructed clothed character. `Tools/reverse/original_animation_probe.py` exports **numeric transforms only**, never images/audio/cards. Five normal states cover standalone clips and two three-way height blend trees, heights 0.2/0.5/0.8 with customized body baselines, four phases and speeds 0/0.75/1.5. `analysis/original_animation_reference.py` maps exact source paths to the converted binding IDs. `SourceOriginalAnimatorTests` applies the native animation to the original baseline and compares all bound local matrices and the clock against that actual player output: **180 cases, 60,804 matrices, maximum matrix-element error 0.0000312, maximum normalized-time error 0.000000060**. This establishes numerical Animator application for those cases, separately from later Studio FK/IK/dynamics and rendered pixel parity.
