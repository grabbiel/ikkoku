## Set up a clean checkout

This is the one documented path from a fresh clone to the public tests and a
Debug app build. It needs no original game data, no `.local/` state and no
variables from an earlier shell session.

1. On an Apple Silicon Mac, install Xcode 26, select it and add its Metal
   Toolchain component:

   ```sh
   sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
   xcodebuild -downloadComponent MetalToolchain
   ```

2. Install a .NET SDK, version 10 or newer, from
   <https://dotnet.microsoft.com/download> so that `dotnet` is on `PATH`. The
   public lane's translation suite builds the Roslyn frontend with it.
3. Clone the repository and check the prerequisites:

   ```sh
   git clone https://github.com/grabbiel/ikkoku.git
   cd ikkoku
   python3 Tools/verification/doctor.py --require public
   ```

   The [checker](../../Tools/verification/README.md#prerequisite-checker-t-t01)
   uses only the Python standard library and runs version probes; it reads no
   `.local/` data and writes nothing. It reports every capability in the table
   below and exits 1 if a public one is unmet, naming the tool and its fix.
   Optional capabilities change the exit status only when selected, for
   example `--require reverse-tools`.
4. Run the public lane, then build the app:

   ```sh
   python3 Tools/verification/run.py --manifest Tools/verification/lanes/public.json
   xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
     -configuration Debug -derivedDataPath .local/build \
     -destination 'platform=macOS,arch=arm64' build
   ```

   The project signs automatically with its configured development team.
   Without that team, append `CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY=""`
   as CI does. CI only checks that such a build compiles and links; launching
   an unsigned build has not been verified. To package a Release build, see
   [Package and inspect a Release build](#package-and-inspect-a-release-build).

CI runs the same checker with `--require public` before the public lane.
Optional workflows have their own entries below and runbooks:
[reverse tools](#test-layers), [managed recovery](../reference/managed-recovery.md),
[asset regeneration](../../Tools/assets/README.md) and the VM probes in the
[extraction runbook](../../Tools/reverse/README.md).

## Prerequisites

The application target declares macOS 14.6, the engine package declares macOS 14
and Swift tools version 6.0, and `IkkokuShaders` declares macOS 26.0. These settings
do not establish a verified minimum macOS version for the combined product.
Resolve the shader deployment mismatch and test older systems in T-T01. If the
checker reports the Metal compiler as `error` (for example "missing Metal
Toolchain"), install the Xcode component with
`xcodebuild -downloadComponent MetalToolchain`.

Bundled assets are already in `Assets/`; Blender and the original game are not
required to build the native app. Asset regeneration has separate prerequisites
in the [asset pipeline runbook](../../Tools/assets/README.md).

## Build and launch

```sh
xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
  -configuration Debug -derivedDataPath .local/build \
  -destination 'platform=macOS,arch=arm64' build
open .local/build/Build/Products/Debug/Ikkoku.app
```

Alternatively open `Ikkoku.xcodeproj` and run the `IkkokuCreator` scheme. The product
is `Ikkoku.app`. `IKKOKU_ASSETS=/absolute/path/to/Assets` overrides the bundled native
asset root when launching the executable directly. Build with `-configuration
Release` for measurements and use the corresponding `Products/Release` executable.

## Package and inspect a Release build

Build the Release app from a clean checkout, then inspect what it would ship:

```sh
git status --short --ignored -- Assets    # expect no output: Xcode copies Assets/ from disk
xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
  -configuration Release -derivedDataPath .local/build-release \
  -destination 'platform=macOS,arch=arm64' ARCHS=arm64 build
python3 Tools/verification/inspect_app_bundle.py \
  .local/build-release/Build/Products/Release/Ikkoku.app \
  --report .local/verification/reports/release-bundle.json
```

The app target copies its `Assets/` folder as a file-system synchronized
group. Untracked or git-ignored files there, such as regenerated `.gltf`/`.bin`
intermediates, are copied too. Until 2026-10-23 the target also listed
`Packages/`, which copied the whole Engine package, tests and fixtures
included, into `Contents/Resources/Engine/`. Any folder added to the app
target's synchronized groups ships its non-source files as resources. The
[inspector](../../Tools/verification/README.md#release-bundle-inspector-t-t02)
fails on any file that is neither a declared build product nor a tracked
asset, so build releases from a clean tree. It also requires the metallib, the
catalog and every catalog-referenced asset, an `arm64` executable, and no
private or original-game content. `ARCHS=arm64` keeps Release to the
Apple Silicon slice; without it, Release also compiles an untested `x86_64`
slice. Append `CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY=""` without the
development team, as CI's `release-package` job does.

Three lookups have **source-tree fallbacks**, which are paths inside the
checkout the binary was compiled from (`#filePath`). The asset root falls back
to `Assets/` when the bundle has no `catalog.json`. Maker and Studio also find
the git-ignored Maker library and original male/female bases under
`.local/reverse/`. These paths exist only on the build machine, so an app moved
elsewhere on that machine still finds them. Every use prints a
`[ikkoku] source-tree fallback:` line. `IKKOKU_SOURCE_TREE_FALLBACKS=0`
disables all three. Explicit `IKKOKU_ASSETS`, `IKKOKU_MAKER_LIBRARY` and
`IKKOKU_SOURCE_AVATAR`/`IKKOKU_SOURCE_MALE_AVATAR` still apply, and so does a
selected converted library (below). Unset or any other value keeps the
development defaults in both configurations.

To check that the bundle alone supplies the app's resources, launch a copy
outside the checkout with the fallbacks off. The thumbnail mode loads the
metallib, the catalog and every catalog entry, renders them offscreen and
exits:

```sh
WORK="$(mktemp -d)"
ditto .local/build-release/Build/Products/Release/Ikkoku.app "$WORK/Ikkoku.app"
(cd "$WORK" && IKKOKU_SOURCE_TREE_FALLBACKS=0 IKKOKU_RENDER_THUMBS="$WORK/thumbs" \
  ./Ikkoku.app/Contents/MacOS/Ikkoku; echo "exit $?")
```

Expect an `[ikkoku] assets root:` line naming the copy's
`Ikkoku.app/Contents/Resources` (possibly with a `/private` prefix), no
`source-tree fallback` line, `… thumbnails written` and exit 0. **This launch
has not been run** (T-T02). CI only builds and inspects the bundle. The
launch also does not cover a clean user profile, signing, notarization or an
installer.

### Use a converted library outside the checkout

Since A-T02 (2026-10-23), File → Choose Converted
Library… selects the folder that holds `maker-library/library.json`,
`rigs/source-avatar.json` and/or `male/source-male-avatar.json`. That is the
`.local/reverse/` layout, copied or moved anywhere. Copy these folders together:

```text
<library>/
  maker-library/                  Maker library (library.json)
  rigs/                           original female base (source-avatar.json)
  male/                           original male base (source-male-avatar.json)
  studio-pose/                    Studio bone catalog (contract.json, attachments.json, ik-bindings.json)
  animation-assets/female-base/   Maker idle animation (animation.json)
```

A scene saved from a source scene inside this folder (for example under
`.local/reverse/studio-scenes/`) records that scene by its path inside the
folder, so copy it too. Otherwise the scene file and every character in it stay
unresolved after the move.

The last two are companion files, not libraries: the app reads them beside the
female base (`rigs/../studio-pose/contract.json` and
`rigs/../animation-assets/female-base/animation.json`). Without `studio-pose/`,
Preview CharaStudio Scene refuses a scene with characters. Without
`animation-assets/`, the Maker shows the original base without its idle
animation. The app records each manifest's and companion's SHA-256 and saves the
selection in user defaults. The Maker library and original-base lookups then read
it after their explicit variables and before the source-tree defaults. It does
not change the asset root. A folder without a companion is still selected; the
app then shows an alert and a status line naming each missing file, and prints
it as a `[ikkoku] converted library:` line. Startup prints a
`[ikkoku] converted library:` line for each selected manifest. It also prints a
`converted library changed since it was selected` line when a manifest's bytes
differ, and one line for each companion that is missing, changed or was not
recorded. An explicit `IKKOKU_SOURCE_AVATAR` (or the source-tree default) without
its companions prints a `[ikkoku] converted layout gap:` line for each missing
one. To inspect or clear the selection, use File → Forget Converted Library or,
with the app quit:

```sh
plutil -p ~/Library/Preferences/com.grabbiel.IkkokuCreator.plist
defaults delete ~/Library/Preferences/com.grabbiel.IkkokuCreator ConvertedLibraryLocation
```

The app is not sandboxed and writes `~/Library/Preferences/`. Do not use the
bare domain (`defaults read com.grabbiel.IkkokuCreator`). When an old sandbox
container `~/Library/Containers/com.grabbiel.IkkokuCreator` exists, the bare
domain reads that container's plist instead; on the development Mac (container
from August 2026) it showed only a window frame. `defaults read
~/Library/Preferences/com.grabbiel.IkkokuCreator` also reads the app's file.

Automated runs ignore a saved selection: any capture or scenario mode, and
`IKKOKU_CAPTURE_UI`. Startup prints `the saved converted library selection is
ignored in an automated run` instead, so a lane's inputs come only from its
environment. Pass the explicit variables to point an automated run at a moved
library.

Scenes saved since A-T02 record each referenced file's SHA-256 and its path
inside the library it came from. Opening such a scene after the library moved
relocates its references into the selected library when the identities match.
Missing, changed or escaping files are listed under Source compatibility details
and printed as `[ikkoku] <scene>: Unresolved …` lines; their objects are not
loaded. The rules are in
[Library location and relocation](../reference/native-assets.md#library-location-and-relocation-a-t02).

Preview CharaStudio Scene… and `IKKOKU_SOURCE_SCENE` print each object they could
not build as a `[ikkoku] <scene>: … retained without rendering: …` line. A scene
with characters is refused when the Studio pose contract is missing (`The Studio
pose contract is missing at …`), so a save can no longer keep the folders and
drop every character. An automated run (capture or scenario) whose scene
characters all failed to build exits 1 naming `IKKOKU_SOURCE_SCENE`, instead of
capturing an empty scene.

Copy or move the whole converted folder, including `studio-pose/`,

## Test layers

```sh
swift test --package-path Packages/Engine
python3 -m unittest discover -s Tools/mods -p 'test_*.py'
python3 -m unittest discover -s Tools/translation/tests -p 'test_*.py'
```

The Swift suite includes synthetic contracts and optional source fixtures. Tests
that need a private fixture run only when every `IKKOKU_*` variable they require is
set to a nonempty path; otherwise they report as *skipped* with a
`Requires IKKOKU_…` reason, so a green run never hides missing source-data coverage.
To audit fixture coverage, run with
`IKKOKU_REQUIRE_SOURCE_FIXTURES=1 swift test --package-path Packages/Engine`:
every fixture-gated test runs and fails on a missing variable, except tests whose
skip gate also requires a Metal device; those still skip without one and report
that reason. Tests that require a device inside the test body fail without one.
Optional output variables such as `IKKOKU_CARD_EDIT_OUTPUT`
are never required by strict mode. Supply fixtures by
exporting the variables listed in the component reports and reference docs
(e.g. `IKKOKU_SHAPE_CONTRACT=/absolute/path/to/character-shape-contract.json`);
Supplied fixture paths must exist; otherwise the gated test fails. Record
executed case counts and input hashes with results; the
[component reports](../component-audit/README.md) map features to their tests.

For the reverse tools, create the pinned Python environment before running their
unit tests or exporters. The recorded compatible interpreter is Python 3.12;
`python3 Tools/verification/doctor.py --require reverse-tools` checks the venv
interpreter and every pin in `requirements.txt` (`--tool reverse-python=PATH`
checks another interpreter):

```sh
python3.12 -m venv .local/reverse/unitypy-venv
.local/reverse/unitypy-venv/bin/python -m pip install -r Tools/reverse/requirements.txt
.local/reverse/unitypy-venv/bin/python -m unittest discover -s Tools/reverse -p 'test_*.py'
.local/reverse/unitypy-venv/bin/python -m unittest discover -s Tools/reverse/analysis -p 'test_*.py'
```

Some reverse scripts named `test_*` are fixture-driven command-line programs, not
unittest cases. Run the commands in the owning reference page to exercise those
checks; discovery does not replace them. Managed recovery uses local ILSpy tools;
the Roslyn translation frontend uses .NET 10 SDK assemblies
(`--require managed-recovery` checks the SDK and both ILSpy versions). See
[managed recovery](../reference/managed-recovery.md) and
[API substitution](../reference/mods/api-substitution.md) for setup and invocations.

## Offscreen and UI captures

These examples use an existing converted static model or native scene. Replace
input paths before running:

```sh
IKKOKU_CAPTURE_MODEL=/absolute/path/to/model.gltf \
IKKOKU_AUTOCAPTURE="$PWD/.local/model.png" \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku

IKKOKU_CAPTURE_SCENE=/absolute/path/to/native-scene.png \
IKKOKU_AUTOCAPTURE="$PWD/.local/scene.png" \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
```

`IKKOKU_CAPTURE_W` and `IKKOKU_CAPTURE_H` set the size of rig, model, native-scene
and app captures. `IKKOKU_CAPTURE_YAW` sets the framing of rig, model and app captures,
not native scenes. `IKKOKU_CAPTURE_MIRROR=1` exercises mirrored static
model rendering. Startup rejects an option the requested mode does not read; see
[capture request validation](#capture-request-validation). The static-model/native-scene capture paths report nonzero status
on handled import/render failures. A static-model capture isolates
asset loading and rendering from Maker assembly.

```sh
IKKOKU_CAPTURE_UI="$PWD/.local/studio-ui.png" IKKOKU_CAPTURE_UI_MODE=studio \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
```

UI capture opens the application window; it is distinct from offscreen rendering.
It waits for readiness rather than a fixed delay. SwiftUI `onAppear` must have
run, and a visible window's laid-out bounds must be nonzero and unchanged for
five polls 0.1 s apart. Otherwise it exits 1 after `IKKOKU_CAPTURE_UI_TIMEOUT`
seconds (default 30, at most 600), naming what was not ready.

Capture outputs are read back after writing: the UI PNG and
`IKKOKU_CAPTURE_UI_REPORT`, thumbnails, offscreen PNGs and JSON reports. Each
must be nonempty and byte-identical to what was written, and a PNG must be
complete and decode at the captured pixel size. A failure prints the path and
exits 1; "written" is printed only after verification. Parent directories are
not created. `IKKOKU_RENDER_THUMBS=<dir>` attempts every catalog entry, lists
each failure and exits 1 if any entry failed or none was written (A-T05).

CI compiles this app path but does not run it. Confirm it on the Mac:

```sh
APP=.local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
# Destination under a missing directory: exit 1, path named, no "written".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-missing/ui.png" "$APP"; echo "exit $?"
# A directory at the destination: exit 1.
mkdir -p .local/a-t05-dir
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-dir" "$APP"; echo "exit $?"
# Forced readiness timeout: exit 1 with "not ready after".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-ui.png" IKKOKU_CAPTURE_UI_TIMEOUT=0.05 "$APP"; echo "exit $?"
# Normal capture: exit 0 after "ui snapshot written" and "ui report written".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-ui.png" \
  IKKOKU_CAPTURE_UI_REPORT="$PWD/.local/a-t05-ui.json" "$APP"; echo "exit $?"
# Thumbnails: exit 0 with the count written; a file in place of the folder exits 1.
IKKOKU_RENDER_THUMBS="$PWD/.local/a-t05-thumbs" "$APP"; echo "exit $?"
touch .local/a-t05-file
IKKOKU_RENDER_THUMBS="$PWD/.local/a-t05-file" "$APP"; echo "exit $?"
```

Source-rig, card, scene, plugin and matched-player capture recipes live with their
[technical references](../README.md#technical-references). Headless captures exit
before `NSApplication` finishes launching. The Mute native adapter therefore defers
its initial focus sample instead of reading `NSApp`; this fixes the recorded
startup trap. `IKKOKU_APPLICATION_FOCUS` and `IKKOKU_NATIVE_PLUGIN_REPORT` supply
and record focus for captures; both require `IKKOKU_AUTOCAPTURE`. The Release adapter captures closing A-T04/ST-T02 passed in PR #2; see
[native adapters](../reference/mods/native-adapters.md#startup-and-acceptance).

### Capture request validation

Before the engine starts, the app checks the whole `IKKOKU_*` environment with
`CaptureRequest.validate`
([CaptureRequest.swift](../../Packages/Engine/Sources/Renderer/CaptureRequest.swift),
A06/A-T06). If anything is wrong it prints one `invalid capture request` message
listing every offending variable, one line per problem, and exits 1. At most one
mode runs per launch:

| Mode | Selected by | Also needs | Capture options it reads |
| --- | --- | --- | --- |
| Original-frame probe | `IKKOKU_ORIGINAL_FRAME_PROBE` | — | `IKKOKU_ORIGINAL_FRAME_FAMILIES`; with `…_FAMILIES=1` also `…_FAMILY_SETS`, `…_TRACE_PIXELS`, `…_DEPTH24` |
| Source rig capture | `IKKOKU_CAPTURE_RIG` | `IKKOKU_AUTOCAPTURE` | `IKKOKU_SOURCE_EXPRESSION`, `IKKOKU_SOURCE_HEIGHT`, `IKKOKU_SOURCE_BODY`, `IKKOKU_SOURCE_FACE`, `IKKOKU_CAPTURE_SHADOWS`, `IKKOKU_RIG_BONES`, `IKKOKU_CAPTURE_PRESET=face`, `…_W`, `…_H`, `…_YAW` |
| Static model capture | `IKKOKU_CAPTURE_MODEL` | `IKKOKU_AUTOCAPTURE` | `IKKOKU_CAPTURE_MIRROR`, `…_W`, `…_H`, `…_YAW` |
| Native scene capture | `IKKOKU_CAPTURE_SCENE` | `IKKOKU_AUTOCAPTURE` | `…_W`, `…_H`, `IKKOKU_SAVE_SCENE`, `IKKOKU_CAPTURE_GRID=0`, `IKKOKU_CAPTURE_GIZMOS=0`, `IKKOKU_NATIVE_PLUGIN_REPORT`, `IKKOKU_APPLICATION_FOCUS` |
| Maker / Studio scenario | `IKKOKU_MAKER_SCENARIO` / `IKKOKU_STUDIO_SCENARIO` | its `…_SCENARIO_REPORT` | — |
| Gameplay scenario (A-T01) | `IKKOKU_GAMEPLAY_SCENARIO` | `IKKOKU_GAMEPLAY_SCENARIO_REPORT` | — (runs before the engine and editors start; startup inputs are ignored) |
| Catalog thumbnails | `IKKOKU_RENDER_THUMBS` | — | — |
| Maker/Studio app capture | `IKKOKU_AUTOCAPTURE` without the rig, model or scene capture | — | every other capture option (below) |
| Window capture | `IKKOKU_CAPTURE_UI`, alone or after an app capture | — | `IKKOKU_CAPTURE_UI_TAB`, `…_MODE`, `…_STUDIO_TAB` (needs `…_MODE=studio`), `…_REPORT`, `…_TIMEOUT` |

The app capture also reads `IKKOKU_CARD`, `IKKOKU_CAPTURE_SEX`,
`IKKOKU_SOURCE_COORDINATE`, `IKKOKU_SOURCE_COLOR_EDITS`,
`IKKOKU_SOURCE_PLAYBACK_SECONDS`, `IKKOKU_CAPTURE_SLIDERS`, `…_EXPR`, `…_OUTFIT`,
`…_HAIR`, `…_PRESET`, `…_TICKS`, `…_GRID` and `…_GIZMOS`. It also reads
`IKKOKU_CAPTURE_STUDIO` and, only with it, `…_POSE`, `…_ITEMS` and `…_TIMELINE`.
`IKKOKU_SOURCE_SCENE_EDITS` needs `IKKOKU_SOURCE_SCENE`. Card, scene and
original-scene outputs are `IKKOKU_EXPORT_SOURCE_CARD`, `IKKOKU_SAVE_CARD`,
`IKKOKU_SAVE_SCENE`, `IKKOKU_LOAD_SCENE` and `IKKOKU_EXPORT_SOURCE_SCENE`.
`IKKOKU_BENCHMARK_OUTPUT` takes `…_FRAMES` and `…_SIMULATION_FRAMES`; the latter
also needs `IKKOKU_SOURCE_SCENE`. Plugin evidence is `IKKOKU_NATIVE_PLUGIN_REPORT`
and `IKKOKU_APPLICATION_FOCUS`.

Startup inputs (`IKKOKU_SOURCE_SCENE`, `IKKOKU_SOURCE_CARD`, `IKKOKU_OPEN_RIG`,
`IKKOKU_BONE_MODIFIERS`, `IKKOKU_MOD_LIBRARY` and the Studio plugin, step and
animation-time inputs) and data sources (`IKKOKU_ASSETS`, avatars, the Maker
library, contracts, Studio catalogs and `IKKOKU_SOURCE_TREE_FALLBACKS`) also
apply to an interactive launch.
One environment file often supplies them to several modes, so a mode that does
not read them ignores them; only an empty value is rejected. Other tools' fixture
variables are ignored. `IKKOKU_SOURCE_PLUGIN_DELTA` still needs
`IKKOKU_SOURCE_PLUGIN_STEPS`.

After validation, a run with any mode or `IKKOKU_CAPTURE_UI` is automated. A
startup or capture input that fails then exits 1 as `capture input failed:
IKKOKU_X=value: error` instead of becoming an alert or being skipped. Examples:
an unreadable `IKKOKU_CARD`, a scene in `IKKOKU_LOAD_SCENE` or one of its items
that does not load, source body or face values without a source contract, and an
unknown slider, hair, pose, catalog item or Maker tab. An out-of-range outfit, an
explicit `IKKOKU_SHAPE_CONTRACT` that is missing, and an explicit
`IKKOKU_SOURCE_AVATAR` or `IKKOKU_SOURCE_MALE_AVATAR` that falls back to the
bundled character also exit. The probe exits when `IKKOKU_ORIGINAL_FRAME_FAMILIES=1`
lacks its translated shaders. An interactive launch keeps the alert.

These combinations used to run and now exit 1 at startup:

- Two modes, such as `IKKOKU_CAPTURE_RIG` with `IKKOKU_CAPTURE_SCENE` (only the
  first ran). Also `IKKOKU_AUTOCAPTURE` with thumbnails, a scenario or the probe
  (the PNG was never written), and `IKKOKU_CAPTURE_UI` with any mode except the
  app capture (the window never opened).
- `IKKOKU_NATIVE_PLUGIN_REPORT` or `IKKOKU_APPLICATION_FOCUS` without
  `IKKOKU_AUTOCAPTURE`. The editor stayed open, and a failed report was only an alert.
- A capture option that no requested mode reads. Examples: `IKKOKU_CAPTURE_W`
  without a mode, `IKKOKU_CAPTURE_MIRROR` outside model capture, and
  `IKKOKU_CAPTURE_YAW`, `…_PRESET` or `IKKOKU_LOAD_SCENE` in native scene capture.
  Others are rig-only options elsewhere, window options without
  `IKKOKU_CAPTURE_UI` and a scenario report without its scenario.
- An option without its partner, listed with each mode above. `IKKOKU_ORIGINAL_FRAME_DEPTH24=1`
  needs `…_FAMILIES=1`.
- In the app capture, `IKKOKU_CARD` with `IKKOKU_SOURCE_CARD`, `IKKOKU_OPEN_RIG`,
  `IKKOKU_BONE_MODIFIERS` or a source-preview edit (body, face, coordinate,
  colors, playback or source-card export). Loading the native card discarded
  that preview. `IKKOKU_CAPTURE_SEX` with `IKKOKU_CARD`, `IKKOKU_SOURCE_CARD`,
  `IKKOKU_OPEN_RIG` or `IKKOKU_BONE_MODIFIERS` either replaced that character or
  was ignored. Rig capture's existing source-card rule now also runs up front.
- Values a mode replaced with its default or ignored. Sizes must be integers in
  1–8192; ticks, outfit and coordinate must be integers of at least 0. Yaw and
  timeline must be finite numbers, and presets one of face, upper or full (rig
  capture: only `face`). Flags must be 0 or 1, `IKKOKU_CAPTURE_SEX` m or f and
  `IKKOKU_CAPTURE_UI_MODE` maker or studio. Expression keys must be eyes, mouth,
  brows, head or gaze, with well-formed `key=value` lists. Focus events must be
  0/1 lists of at most 64. Native scene capture rejects `GRID=1` and `GIZMOS=1`.
- Empty values and unknown `IKKOKU_CAPTURE_*`, `IKKOKU_ORIGINAL_FRAME_*` or
  `IKKOKU_BENCHMARK_*` names.

No recipe in this guide, the [technical references](../README.md#technical-references),
`Tools/reverse/README.md` or `Tools/translation/studio_execution_probe.py` uses
one of these. Of the verification lanes, only the `app-smoke`
`startup-mute-capture` check did: it set the adapter report without a capture,
so the app would have stayed open. It now also writes a Maker PNG. `CaptureRequestTests` keeps 31 such recipes valid in CI,
and `Tools/verification/test_run.py` checks that the inventory matches the
variables the app reads. CI compiles the app but does not run it. Confirm on the Mac:

```sh

# Two modes: exit 1 naming both, before "assets root" is printed.
IKKOKU_CAPTURE_RIG=/nonexistent/rig.json IKKOKU_CAPTURE_SCENE=/nonexistent/scene.png \
  IKKOKU_AUTOCAPTURE="$PWD/.local/a-t06.png" "$APP"; echo "exit $?"
# Adapter report without a capture: exit 1 at once; no window opens.
IKKOKU_NATIVE_PLUGIN_REPORT="$PWD/.local/a-t06-report.json" "$APP"; echo "exit $?"
# A capture option without a mode: exit 1.
IKKOKU_CAPTURE_W=900 "$APP"; echo "exit $?"
# Missing native card or scene: exit 1 naming IKKOKU_CARD / IKKOKU_LOAD_SCENE; no PNG.
IKKOKU_CARD="$PWD/.local/a-t06-missing.png" IKKOKU_AUTOCAPTURE="$PWD/.local/a-t06-card.png" "$APP"; echo "exit $?"
IKKOKU_LOAD_SCENE="$PWD/.local/a-t06-missing.png" IKKOKU_AUTOCAPTURE="$PWD/.local/a-t06-scene.png" "$APP"; echo "exit $?"

# A plain Maker capture still exits 0.
```

### Gameplay host scenario

`IKKOKU_GAMEPLAY_SCENARIO` runs a JSON `SourceGameplayHostScenario` through the
native [gameplay host](../reference/gameplay/cycle.md#gameplay-host-a-t01)
(A-T01) before the engine and editors start, so it needs no Metal device or
converted assets. Reload steps with a `path` write the host snapshot there and
resume from the file read back. The report at `IKKOKU_GAMEPLAY_SCENARIO_REPORT`
lists every step, reload and host trace entry. The app exits 0 only when every
step passed. The Engine suite runs the same shipped scenario in CI; the app run
is the `gameplay-scenarios` lane (not yet run on the Mac):

```sh
python3 Tools/verification/run.py --manifest Tools/verification/lanes/gameplay-scenarios.json
# or directly, after the Debug build:
IKKOKU_GAMEPLAY_SCENARIO=Tools/verification/scenarios/gameplay-controlled-event.json \
  IKKOKU_GAMEPLAY_SCENARIO_REPORT="$PWD/.local/verification/reports/gameplay-scenario-controlled-event.json" \
  "$APP"; echo "exit $?"   # expect 0 and "17 passed, 0 failed"
# Without the report: exit 1 naming IKKOKU_GAMEPLAY_SCENARIO.
IKKOKU_GAMEPLAY_SCENARIO=Tools/verification/scenarios/gameplay-controlled-event.json "$APP"; echo "exit $?"
```

Run it from the repository root: the scenario's snapshot paths are relative
(`.local/verification/gameplay/`).

## Inspect without the GUI

```sh
swift run --package-path Packages/Engine ikkoku-inspect model /absolute/path/to/model.gltf
swift run --package-path Packages/Engine ikkoku-inspect scene /absolute/path/to/source-scene.png
swift run --package-path Packages/Engine ikkoku-inspect scene-document /absolute/path/to/source-scene.png
swift run --package-path Packages/Engine ikkoku-inspect rig /absolute/path/to/rig.json
```

`scene` reads the object section; `scene-document` includes the supported scene
settings tail and retained extension data. Decoding success is not scene rendering
coverage. Keep original content, generated fixtures, captures and build output in
ignored `.local/`. Performance comparisons must record configuration, machine,
resolution, scene contents, simulation work and renderer path; do not extrapolate
a static fixture to full-game frame time.
