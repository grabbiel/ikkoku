## Set up a clean checkout

This is the one documented path from a fresh clone to the public tests and a
Debug app build. It needs no original game data, no `.local/` state and no
variables from an earlier shell session.

1. On an Apple Silicon Mac, install Xcode 26, select it and add its Metal
   Toolchain component:

   ```sh
   sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
   xcodebuild -downloadComponent MetalToolchain
   ```

2. Install a .NET SDK, version 10 or newer, from
   <https://dotnet.microsoft.com/download> so that `dotnet` is on `PATH`. The
   public lane's translation suite builds the Roslyn frontend with it.
3. Clone the repository and check the prerequisites:

   ```sh
   git clone https://github.com/grabbiel/ikkoku.git
   cd ikkoku
   python3 Tools/verification/doctor.py --require public
   ```

   The [checker](../../Tools/verification/README.md#prerequisite-checker-t-t01)
   uses only the Python standard library and runs version probes; it reads no
   `.local/` data and writes nothing. It reports every capability in the table
   below and exits 1 if a public one is unmet, naming the tool and its fix.
   Optional capabilities change the exit status only when selected, for
   example `--require reverse-tools`.
4. Run the public lane, then build the app:

   ```sh
   python3 Tools/verification/run.py --manifest Tools/verification/lanes/public.json
   xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
     -configuration Debug -derivedDataPath .local/build \
     -destination 'platform=macOS,arch=arm64' build
   ```

   The project signs automatically with its configured development team.
   Without that team, append `CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY=""`
   as CI does. CI only checks that such a build compiles and links; launching
   an unsigned build has not been verified. To package a Release build, see
   [Package and inspect a Release build](#package-and-inspect-a-release-build).

CI runs the same checker with `--require public` before the public lane.
Optional workflows have their own entries below and runbooks:
[reverse tools](#test-layers), [managed recovery](../reference/managed-recovery.md),
[asset regeneration](../../Tools/assets/README.md) and the VM probes in the
[extraction runbook](../../Tools/reverse/README.md).

## Prerequisites

The application target declares macOS 14.6, the engine package declares macOS 14
and Swift tools version 6.0, and `IkkokuShaders` declares macOS 26.0. These settings
do not establish a verified minimum macOS version for the combined product.
Resolve the shader deployment mismatch and test older systems in T-T01. If the
checker reports the Metal compiler as `error` (for example "missing Metal
Toolchain"), install the Xcode component with
`xcodebuild -downloadComponent MetalToolchain`.

Bundled assets are already in `Assets/`; Blender and the original game are not
required to build the native app. Asset regeneration has separate prerequisites
in the [asset pipeline runbook](../../Tools/assets/README.md).

## Build and launch

```sh
xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
  -configuration Debug -derivedDataPath .local/build \
  -destination 'platform=macOS,arch=arm64' build
open .local/build/Build/Products/Debug/Ikkoku.app
```

Alternatively open `Ikkoku.xcodeproj` and run the `IkkokuCreator` scheme. The product
is `Ikkoku.app`. `IKKOKU_ASSETS=/absolute/path/to/Assets` overrides the bundled native
asset root when launching the executable directly. Build with `-configuration
Release` for measurements and use the corresponding `Products/Release` executable.

## Package and inspect a Release build

Build the Release app from a clean checkout, then inspect what it would ship:

```sh
git status --short --ignored -- Assets    # expect no output: Xcode copies Assets/ from disk
xcodebuild -project Ikkoku.xcodeproj -scheme IkkokuCreator \
  -configuration Release -derivedDataPath .local/build-release \
  -destination 'platform=macOS,arch=arm64' ARCHS=arm64 build
python3 Tools/verification/inspect_app_bundle.py \
  .local/build-release/Build/Products/Release/Ikkoku.app \
  --report .local/verification/reports/release-bundle.json
```

The app target copies its `Assets/` folder as a file-system synchronized
group. Untracked or git-ignored files there, such as regenerated `.gltf`/`.bin`
intermediates, are copied too. The
[inspector](../../Tools/verification/README.md#release-bundle-inspector-t-t02)
fails on any file that is neither a declared build product nor a tracked
asset, so build releases from a clean tree. It also requires the metallib, the
catalog and every catalog-referenced asset, an `arm64` executable, and no
private or original-game content. `ARCHS=arm64` keeps Release to the
Apple Silicon slice; without it, Release also compiles an untested `x86_64`
slice. Append `CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY=""` without the
development team, as CI's `release-package` job does.

Three lookups have **source-tree fallbacks**, which are paths inside the
checkout the binary was compiled from (`#filePath`). The asset root falls back
to `Assets/` when the bundle has no `catalog.json`. Maker and Studio also find
the git-ignored Maker library and original male/female bases under
`.local/reverse/`. These paths exist only on the build machine, so an app moved
elsewhere on that machine still finds them. Every use prints a
`[ikkoku] source-tree fallback:` line. `IKKOKU_SOURCE_TREE_FALLBACKS=0`
disables all three. Explicit `IKKOKU_ASSETS`, `IKKOKU_MAKER_LIBRARY` and
`IKKOKU_SOURCE_AVATAR`/`IKKOKU_SOURCE_MALE_AVATAR` still apply. Unset or any
other value keeps the development defaults in both configurations.

To check that the bundle alone supplies the app's resources, launch a copy
outside the checkout with the fallbacks off. The thumbnail mode loads the
metallib, the catalog and every catalog entry, renders them offscreen and
exits:

```sh
WORK="$(mktemp -d)"
ditto .local/build-release/Build/Products/Release/Ikkoku.app "$WORK/Ikkoku.app"
(cd "$WORK" && IKKOKU_SOURCE_TREE_FALLBACKS=0 IKKOKU_RENDER_THUMBS="$WORK/thumbs" \
  ./Ikkoku.app/Contents/MacOS/Ikkoku; echo "exit $?")
```

Expect an `[ikkoku] assets root:` line naming the copy's
`Ikkoku.app/Contents/Resources` (possibly with a `/private` prefix), no
`source-tree fallback` line, `… thumbnails written` and exit 0. **This launch
has not been run** (T-T02). CI only builds and inspects the bundle. The
launch also does not cover a clean user profile, signing, notarization or an
installer.

## Test layers

```sh
swift test --package-path Packages/Engine
python3 -m unittest discover -s Tools/mods -p 'test_*.py'
python3 -m unittest discover -s Tools/translation/tests -p 'test_*.py'
```

The Swift suite includes synthetic contracts and optional source fixtures. Tests
that need a private fixture run only when every `IKKOKU_*` variable they require is
set to a nonempty path; otherwise they report as *skipped* with a
`Requires IKKOKU_…` reason, so a green run never hides missing source-data coverage.
To audit fixture coverage, run with
`IKKOKU_REQUIRE_SOURCE_FIXTURES=1 swift test --package-path Packages/Engine`:
every fixture-gated test runs and fails on a missing variable, except tests whose
skip gate also requires a Metal device; those still skip without one and report
that reason. Tests that require a device inside the test body fail without one.
Optional output variables such as `IKKOKU_CARD_EDIT_OUTPUT`
are never required by strict mode. Supply fixtures by
exporting the variables listed in the component reports and reference docs
(e.g. `IKKOKU_SHAPE_CONTRACT=/absolute/path/to/character-shape-contract.json`);
Supplied fixture paths must exist; otherwise the gated test fails. Record
executed case counts and input hashes with results; the
[component reports](../component-audit/README.md) map features to their tests.

For the reverse tools, create the pinned Python environment before running their
unit tests or exporters. The recorded compatible interpreter is Python 3.12;
`python3 Tools/verification/doctor.py --require reverse-tools` checks the venv
interpreter and every pin in `requirements.txt` (`--tool reverse-python=PATH`
checks another interpreter):

```sh
python3.12 -m venv .local/reverse/unitypy-venv
.local/reverse/unitypy-venv/bin/python -m pip install -r Tools/reverse/requirements.txt
.local/reverse/unitypy-venv/bin/python -m unittest discover -s Tools/reverse -p 'test_*.py'
.local/reverse/unitypy-venv/bin/python -m unittest discover -s Tools/reverse/analysis -p 'test_*.py'
```

Some reverse scripts named `test_*` are fixture-driven command-line programs, not
unittest cases. Run the commands in the owning reference page to exercise those
checks; discovery does not replace them. Managed recovery uses local ILSpy tools;
the Roslyn translation frontend uses .NET 10 SDK assemblies
(`--require managed-recovery` checks the SDK and both ILSpy versions). See
[managed recovery](../reference/managed-recovery.md) and
[API substitution](../reference/mods/api-substitution.md) for setup and invocations.

## Offscreen and UI captures

These examples use an existing converted static model or native scene. Replace
input paths before running:

```sh
IKKOKU_CAPTURE_MODEL=/absolute/path/to/model.gltf \
IKKOKU_AUTOCAPTURE="$PWD/.local/model.png" \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku

IKKOKU_CAPTURE_SCENE=/absolute/path/to/native-scene.png \
IKKOKU_AUTOCAPTURE="$PWD/.local/scene.png" \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
```

`IKKOKU_CAPTURE_W`, `IKKOKU_CAPTURE_H` and `IKKOKU_CAPTURE_YAW` control dimensions
and framing where supported. `IKKOKU_CAPTURE_MIRROR=1` exercises mirrored static
model rendering. The static-model/native-scene capture paths report nonzero status
on handled import/render failures. A static-model capture isolates
asset loading and rendering from Maker assembly.

```sh
IKKOKU_CAPTURE_UI="$PWD/.local/studio-ui.png" IKKOKU_CAPTURE_UI_MODE=studio \
  .local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
```

UI capture opens the application window; it is distinct from offscreen rendering.
It waits for readiness rather than a fixed delay. SwiftUI `onAppear` must have
run, and a visible window's laid-out bounds must be nonzero and unchanged for
five polls 0.1 s apart. Otherwise it exits 1 after `IKKOKU_CAPTURE_UI_TIMEOUT`
seconds (default 30, at most 600), naming what was not ready.

Capture outputs are read back after writing: the UI PNG and
`IKKOKU_CAPTURE_UI_REPORT`, thumbnails, offscreen PNGs and JSON reports. Each
must be nonempty and byte-identical to what was written, and a PNG must be
complete and decode at the captured pixel size. A failure prints the path and
exits 1; "written" is printed only after verification. Parent directories are
not created. `IKKOKU_RENDER_THUMBS=<dir>` attempts every catalog entry, lists
each failure and exits 1 if any entry failed or none was written (A-T05).

CI compiles this app path but does not run it. Confirm it on the Mac:

```sh
APP=.local/build/Build/Products/Debug/Ikkoku.app/Contents/MacOS/Ikkoku
# Destination under a missing directory: exit 1, path named, no "written".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-missing/ui.png" "$APP"; echo "exit $?"
# A directory at the destination: exit 1.
mkdir -p .local/a-t05-dir
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-dir" "$APP"; echo "exit $?"
# Forced readiness timeout: exit 1 with "not ready after".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-ui.png" IKKOKU_CAPTURE_UI_TIMEOUT=0.05 "$APP"; echo "exit $?"
# Normal capture: exit 0 after "ui snapshot written" and "ui report written".
IKKOKU_CAPTURE_UI="$PWD/.local/a-t05-ui.png" \
  IKKOKU_CAPTURE_UI_REPORT="$PWD/.local/a-t05-ui.json" "$APP"; echo "exit $?"
# Thumbnails: exit 0 with the count written; a file in place of the folder exits 1.
IKKOKU_RENDER_THUMBS="$PWD/.local/a-t05-thumbs" "$APP"; echo "exit $?"
touch .local/a-t05-file
IKKOKU_RENDER_THUMBS="$PWD/.local/a-t05-file" "$APP"; echo "exit $?"
```

Source-rig, card, scene, plugin and matched-player capture recipes live with their
[technical references](../README.md#technical-references). Headless captures exit
before `NSApplication` finishes launching. The Mute native adapter therefore defers
its initial focus sample instead of reading `NSApp`; this fixes the recorded
startup trap. `IKKOKU_APPLICATION_FOCUS` and `IKKOKU_NATIVE_PLUGIN_REPORT` supply
and record focus for captures. The Release adapter captures closing A-T04/ST-T02 passed in PR #2; see
[native adapters](../reference/mods/native-adapters.md#startup-and-acceptance).

## Inspect without the GUI

```sh
swift run --package-path Packages/Engine ikkoku-inspect model /absolute/path/to/model.gltf
swift run --package-path Packages/Engine ikkoku-inspect scene /absolute/path/to/source-scene.png
swift run --package-path Packages/Engine ikkoku-inspect scene-document /absolute/path/to/source-scene.png
swift run --package-path Packages/Engine ikkoku-inspect rig /absolute/path/to/rig.json
```

`scene` reads the object section; `scene-document` includes the supported scene
settings tail and retained extension data. Decoding success is not scene rendering
coverage. Keep original content, generated fixtures, captures and build output in
ignored `.local/`. Performance comparisons must record configuration, machine,
resolution, scene contents, simulation work and renderer path; do not extrapolate
a static fixture to full-game frame time.
