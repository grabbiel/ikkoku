This revision establishes a working path from observed game data to native props,
scene layouts, original normal female/male bases with complete recovered Maker
body destinations, guarded card appearance and edited-card persistence, plus

## Working native path

1. `vm_source.py` inventories and copies explicit source files with hash verification.
2. `catalog.py` resolves original item keys from selected serialized catalog tables.
3. `export_prefab.py` converts a selected static prefab to glTF, preserving raw
   geometry/material/transform provenance alongside its converted asset catalog.
4. The native loader validates buffers and graphs, loads external PNGs, retains
   authored matrices/signed scale, and respects the active glTF scene.
5. Metal renders the original chair: 679 vertices, 628 triangles, base texture and
   decoded normal texture with verified source cutout behavior.
   Mirrored rendering was also captured and visually checked.
6. Complete current-format original scenes can be inspected, including characters,
   routes and scene settings. Prop/folder layouts resolve through a converted
   catalog; a separate character preview restores supported shape/ABMX/FK settings
   onto the selected clothed avatar and reports remaining compatibility gaps.

Studio has new File commands for static models and CharaStudio object layouts.
Imported rotations retain exact quaternions until an Euler edit; deep native
hierarchies are no longer silently truncated at 64 parents. Native scene loading
rejects cyclic/duplicate/missing-parent graphs, scene imports remap timeline
objects, and subtree deletion removes their animation tracks.

Renderer repairs cover model-space tangent transformation, mirrored culling and
tangent handedness, imported MASK/BLEND/double-sided handling, and blended eyes.
The pre-existing Swift compiler timeout in mouth-weight evaluation was repaired.
Original shader lighting has not been matched; see the shader evidence below.

hair parenting and inactive/default exclusions follow recovered source logic.

**File → Open Source Rig…** also opens individual converted rigs. The Maker offers
Full/Upper/Face cameras, skeleton display, reset and sliders. All 52 face controls

## Mod compatibility requirement

The end product must preserve original moddability as closely as practical. Content
mods need a versioned discovery, dependency resolution and conversion pipeline;
retained original catalog IDs, GUIDs, transform names and morph-channel identity
are compatibility contracts. Converted resources must retain source hashes and
conversion-version records so changed mods can be rebuilt without stale caches.
Managed plug-ins require inspection of referenced APIs and explicit native
extension equivalents; decompilation alone does not make Unity/BepInEx code
executable in Swift + Metal. Unsupported behavior must produce a compatibility
report rather than silently executing a partial conversion.

The `Tools/mods/zipmod.py` importer now preserves bounded ZIP contents,
manifest metadata/migrations, source catalogs and original bundle identities. Its
optional Texture2D adapter writes hashed PNGs and a versioned package manifest.
Swift `SourceModPackage` validates that package and its resource hashes;
`SourceModLibrary` resolves textures by exact bundle/asset identity in an explicitly
chosen mount order. Appearance `modPackages` and `textureBindings` connect these
resources to native shader inputs. Missing bindings fail visibly. A supported
texture conversion does not imply that an entire mod's behavior works.

`Tools/mods/library.py` now discovers newly added local archives on rescan, hashes
their bytes, reuses verified unchanged conversions and creates immutable
generations for changed content or converters. Profiles retain explicit version
choices and mount order. Maker loads/reloads these profiles and displays conflicts,
catalog rows and dependency coverage. Converter 1.1.0 preserves original ZIP bundle
registration order, including source aliases with non-`abdata` prefixes.

`SourceModCatalog` reparses the source CSV format and retains original
GUID/category/slot/property identities instead of temporary runtime IDs. Its
bounded recovered contract contains 107 keys, 71 category mappings and 39 typed
reference rules. The tested catalog-only mod exposes four rows and eight
references: two verified base assets awaiting conversion and six unindexed
dependencies. Prefab selection/rendering is not implied by catalog indexing.

The current ABMX 5.4 card/outfit `boneData` formats now convert to native modifiers.
The static evaluator applies scale, length, position and rotation after the Maker
body/face pose, preserving source bone names and outfit entries. Maker can load,
disable or clear them. Eight independent source-space matrix fixtures verify the
formulas; a synthetic source-format example renders on the original clothed avatar.
Dynamic/accessory modifiers fail explicitly. Native MessagePack and raw LZ4 readers
now recover these modifiers directly from original card `KKEx` blocks or legacy
trailers; an offline JSON conversion is no longer required for card settings.
Unknown blocks, plug-ins and trailers remain in the original retained bytes.
Edited original-card export now preserves those Extended Save records alongside
shape/color edits. Arbitrary card-selected appearance and plug-in execution
remain unimplemented.

Card imports now decode UniversalAutoResolver records and match them to actual
face, body, hair, base-makeup, clothing and accessory destinations in the serialized
card. The native profile resolves saved GUID/source-slot identities using the
destination's category, with first-record and first-catalog-row precedence.
Runtime local slots are retained only as evidence. Maker and `ikkoku-inspect card-mods`
report matching rows, source-only dependencies and unresolved references; changing
the mounted library refreshes the report. This does not yet apply the card's asset
selections or run source migration/compatibility fallback logic.

The installed survey covers 4,202 archives, with three bounded manifest samples
and three managed-plugin metadata inspections. Two local archives are mounted;
the pupil sample provides two textures and the catalog-only sample four rows.
This is not validation of the entire installed collection. Automatic source
version priority, migrations, full asset/material adapters, remaining ABMX behavior
and general managed-plugin rewriting remain unfinished.
