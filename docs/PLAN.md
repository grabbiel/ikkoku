# Ikkoku — Architecture and workplan

Native macOS app, Swift 6 + Metal. One app, two modes: **Maker** and **Studio**.

## Architecture

```
Apps/Ikkoku                SwiftUI shell, viewport host, panels, document I/O
Packages/Engine
  ShaderTypes   C header shared by Swift + Metal (buffer indices, uniforms)
  CoreMath      transforms, quaternions, rays, AABB, IK math
  GPU           device/queue, frame ring, texture loader, pipeline cache
  Assets        GLB loader (meshes, skins, morph targets, materials, images)
  Scene         nodes, cameras, lights, skeleton/pose, IK, picking
  Character     character card model, slider registry, catalog, PNG cards
  Renderer      frame graph: skin/morph compute → shadow → toon+outline →
                transparent → post (bloom, FXAA) → gizmos; ID picking pass
  Studio        scene document, object tree, gizmo interaction, undo, capture
Shaders/        .metal sources compiled into IkkokuShaders.metallib
Tools/assets/   Blender (headless) + numpy pipeline that generates every asset
Assets/         generated GLB/PNG assets + catalog.json (checked in)
```

### Rendering pipeline (per frame)
1. **Deform compute**: for each character mesh, `base + Σ w_i·morph_i`, then
   linear-blend skinning with per-bone matrices (`world · scale · invBind`).
   Output: skinned position/normal/tangent buffer reused by all passes.
2. **Shadow**: directional light, one 2048² depth map, PCF 3×3.
3. **Main**: opaque toon materials (skin, hair, cloth, eye, item) + inverted-hull
   outlines in the same pass (front-face culled, extruded along normal with
   screen-constant width). Reverse-Z, MSAA 4×.
4. **Transparent**: eye highlights, hair alpha edges, glass; depth test, no write.
5. **Post**: bloom (threshold + 4 mip blur), vignette, colour grade, FXAA.
6. **Overlay**: grid, gizmos, bone handles, selection outline.
7. **Picking**: ID render on demand (mouse down) into an R32Uint target.

### Toon material model (Koikatsu-style)
`lit = smoothstep(t−s, t+s, NdotL · shadowMap)`; `color = mix(base·shadowTint, base, lit)`
`+ stepped specular (skin soft, cloth hard, hair anisotropic band)`
`+ rim = pow(1−NdotV, p) · lightMask · rimColor`; outline colour = darkened base.

### Data model
* `CharacterCard` (Codable): face/body slider values keyed by slider id, hair
  parts + colours, outfits (7) × slots, accessories (20), profile. Saved as
  PNG with an `iTXt` chunk `ikkoku:card` holding JSON.
* `SliderRegistry`: id → (kind: morph | boneScale | boneOffset, target, range).
* `StudioScene` (Codable): object tree (characters, items, lights, cameras,
  folders), per-character pose/expression/clothing state, camera slots,
  scene effects. Saved as PNG with `ikkoku:scene`.

## Workplan (concurrent tracks)

| Track | Owner | Deliverable | Depends on |
|-------|-------|-------------|-----------|
| A. Asset pipeline | subagent (Blender/numpy) | `Assets/Characters/body_f.glb`, `body_m.glb` (rig, weights, morphs), hair, clothes, accessories, textures, `catalog.json`, verification renders | ASSET_SPEC.md |
| B. Engine core | main | GLB loader, deform compute, toon renderer, shadow, outline, post, picking | ShaderTypes |
| C. Character model + Maker UI | main | card model, slider registry, PNG cards, tabbed maker | A (catalog), B |
| D. Studio | main (+subagent for gizmo/IK math) | scene doc, tree, gizmos, FK/IK, lights, camera slots, capture, PNG scenes | B, C |
| E. Verification | main | build, launch, screenshots, fix passes | all |

### Milestones
1. **M1 Viewer**: load body_f.glb, toon shading, outline, orbit camera. (B)
2. **M2 Maker**: sliders drive morphs/bone scales, hair/clothes swap, colours,
   save/load PNG card. (A+C)
3. **M3 Studio**: add characters/items/lights, gizmos, FK/IK, expressions,
   capture, scene save/load. (D)
4. **M4 Polish**: post effects, presets, randomiser, keyboard shortcuts,
   app icon, docs.

## Coding rules
* Reverse-Z everywhere; infinite far plane.
* All GPU-visible structs live in `ShaderTypes.h`; Swift never hand-lays them out.
* Render thread owns GPU state; UI thread publishes immutable snapshots
  through `EngineHost` under a lock. No SwiftUI types below the App layer.
* Every asset is generated by a script in `Tools/assets`; nothing hand-edited.

pipeline with outlines/shadows/bloom/FXAA, picking, offscreen capture), maker
