# Character, Maker, cards, and asset mods

Audit date: 2026-09-25. This is a source review of the current working tree, including uncommitted implementation. It is not a fresh test-run report. Test names below identify existing checks; private source comparisons often return early or are disabled unless their `IKKOKU_*` fixture variables are supplied. A default green package run therefore does not prove original-game parity.

Statuses follow the audit-wide vocabulary: **Pending** means no executable implementation of the named feature; **Infancy** means initial infrastructure or a prototype exists; **Mid-stage** means a usable subset exists with material gaps; **Fully ported** applies only to the explicitly bounded original behavior named in that row and its evidence. Native-only utilities may be complete for their own format, but that does not make them ports of Koikatsu.

The important distinction in this area is between `CharacterCard` / `CharacterInstance` and `SourceCharacterCard` / `SourceRigPreview`. The former are the bundled native prototype with its own catalog, sliders, materials and PNG/JSON format. The latter preserve and evaluate recovered original data. A feature appearing in the prototype UI does not mean the corresponding source feature is implemented.

## Specific review notes to preserve when implementing

1. **Do not use fallback geometry as coverage evidence.** `MakerModel.openSourceRig` catches preparation/material errors and can keep the reference assembly; `SourceMakerLibrary.prepare` keeps reference hair/clothes when a selected entry is unavailable. This preserves editability and source identity, but a rendered character may not represent the imported card's selection. Acceptance needs zero unexpected fallback diagnostics for the tested card.
2. **Keep shape-setter completeness separate from assembly completeness.** The body controller is substantially further along than old height-only comments suggest. Full binding of 44 slots is checked before original-card import; it says nothing about missing selected garments, low-detail bodies, special assembly types or physics.
3. **Preserve opaque bytes and source identities across every new editor.** `LocalSlot` is a runtime load-order counter, not a save identity. Existing color/shape editors deliberately avoid asset-ID writes. Exported source thumbnails can depict supported fallback material while unchanged bytes select an unsupported original asset; the diagnostics are consequential.
4. **Audit Unicode identity consistently.** Maker selection and resolver indexes deliberately key on `Data(utf8)`, but `SourceModLibrary` duplicate-GUID detection uses `Set<String>`, and `SourceModCatalog.Key` uses synthesized String equality for some diagnostic/grouping paths. Swift canonical equivalence can treat two different source byte strings as equal. The exact resolver lookup already avoids that; extend the same rule through mounting/profiles/UI IDs before claiming complete ordinal identity parity.
5. **Material reconstruction has two separate stages.** Card albedo composition on CPU/Metal is not the character draw shader. Do not infer original shader/lighting coverage from `appearance.json`, a populated `appliedFields` set or a passing composition oracle. Source-linear is presently restricted to measured recipe families.
6. **Source animation and dynamics are stateful at the caller.** Maker's current selected-geometry branch disables its base dynamics binding instead of remapping it. Reloading a new library is not sufficient to restore animation/dynamics for all assembled hair. Use exact source IDs and fresh baselines, and test seek/reset/outfit replacement.
7. **ABMX preservation is intentionally stricter than preview toggles.** Original-card export refuses an altered or disabled original modifier payload because that would save a card different from the visible pose. A future ABMX editor needs a writer for the actual selected plugin payload, including current/legacy precedence, rather than simply serializing the native JSON adapter.
8. **The two PNG formats must remain explicit.** `CardIO` is the native JSON-chunk format; `SourceCharacterCard` is the original append/block format. The `CardIO` comment “like Koikatsu” describes the visual card concept, not compatible encoding.
9. **Several source comments remain narrower than current behavior.** `SourceRigCustomization` still speaks from the first height operation, `SourceFaceShapePose` still names head-00, and the customization reader comment says appearance is future work even though separate adapters now exist. The [character references](../reference/character/contracts.md) were reconciled with the current implementation on 2026-09-25. Update the remaining source comments to point to the current owners; do not delete the conservative generic direct-target map just to make counts look complete.
10. **Imported archive parser and runtime CSV parser intentionally differ.** The Python importer offers a general decoded CSV inventory, including CP932 fallback; the native catalog injection uses recovered StreamReader/naive comma-split semantics. Only raw preserved bytes should feed source behavior. “Parsed catalog” is not proof it can be injected.
