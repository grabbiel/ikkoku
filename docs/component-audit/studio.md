# Studio component audit

Audit date: 2026-09-25. Scope: the working tree, including uncommitted implementation. This audit inspected every file in `Packages/Engine/Sources/Studio`, the app's `Studio` directory, the two Scene IK implementations, the associated tests, and the recovery tools listed below. It reviewed existing local measurements; it did not rerun the complete test suite. Original files and numeric/reference artifacts remain private under `.local/`.

Status means **Pending** (no native consumer), **Infancy** (initial data path or prototype), **Mid-stage** (substantial implementation with integration, coverage or parity gaps), or **Fully ported** (only the precisely named, bounded source behavior has implementation and source evidence). A native utility can be implementation-complete without being an original-game port. A parser or a retained byte field does not establish runtime support.

## Findings that change the completion assessment

- **ST-B01 — gate removed 2026-09-25; live mouse interaction unverified.** With a source character selected, `StudioView` renders `SourcePoseInspector` (Original kinematics) instead of the old "full-body IK not connected" placeholder, a "Source face editing is not supported yet…" note on Face, and mounted accessory labels on Clothes. Evidence is the `IKKOKU_CAPTURE_UI_*` JSON reports under `.local/st-t01/` (`{pose,face,clothes,object,scene}.json`, fixture `synthetic-current.png` + `source-avatar.json`): each now records the actually-rendered view as `inspectorView` (`displayedInspectorView`, set by that branch's `onAppear`) alongside the model-computed `expectedInspectorView`. Re-inserting the old gate in `StudioView` makes the report differ — the pose run printed `[ikkoku] ui report: inspector mismatch expected=SourcePoseInspector displayed=ObjectInspector` with `inspectorView` no longer `SourcePoseInspector` while `expectedInspectorView` still was — and was reverted afterwards. The window PNGs are not evidence of inspector state: `cacheDisplay(in:to:)` omits most SwiftUI content (toolbar and timeline only), per ST-D07. Mouse-driven guide editing, undo/redo, save/reload and original-scene export remain unverified (ST-T01 open).
- **ST-B02 — native Mute adapter startup trap (verified in PR #2 acceptance).** `StudioModel+Plugins.configureSourceMutePlugin(configuration:)` read `NSApp.isActive` while AppState initialization precedes creation of `NSApplication`; environment/capture mounts and `captureScene` saved-scene restores all reached it. The actual release launch with the native adapter failed with SIGTRAP; evidence is `.local/reverse/plugin-execution/native-adapter-capture-01` and `Ikkoku-2026-09-25-071053.ips`. The mount now defers the initial focus sample to `didFinishLaunching` when `NSApp` is nil (see ST-T02). The release probe now passes for installed-disabled and explicit-enabled configurations (head `93e6b06`, merged `aa4bcb9`); see the verified acceptance section in the native-adapter reference. The successful `release-capture-01` exercised the typed IR fixture, not this adapter mount.
- **ST-B03 — a loaded original scene is still a selective preview.** Source characters outside routes can render. Items, lights, object cameras and routes remain named folders in this import path; route descendants are deliberately unrendered. Current camera and ten camera slots are applied, while maps, original lighting/effects and scene audio remain parsed data.
- **ST-B04 — gated; mouse-driven editing unverified.** The inspector controls that could write prototype-only fields (`card`, `clothingVisible`, `accessoriesVisible`, `animationPreset`, `handGesture`, `expression`) and Timeline keyframes are gated for source characters; viewport gizmos use the existing source callbacks. Native characters keep all these controls, and `snapshotWindowIfRequested` now reports the actually-rendered inspector in the JSON report instead of deriving it from model state alone. When `IKKOKU_SOURCE_SCENE` is loaded, a source character is selected automatically and `IKKOKU_CAPTURE_UI_STUDIO_TAB` picks the inspected tab; mouse-driven editing, undo/redo, save/reload and export remain unverified.
